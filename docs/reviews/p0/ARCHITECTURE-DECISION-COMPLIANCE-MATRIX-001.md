## 2. Status and severity definitions

- **COMPLIANT:** direct evidence demonstrates the approved control for the audited scope.
- **PARTIAL:** some related mechanism exists, but one or more required controls are missing or unverified.
- **NON-COMPLIANT:** inspected implementation directly conflicts with the approved decision.
- **NOT EVIDENCED:** no sufficient implementation evidence was located in the inspected source scope. This is not proof that no implementation exists elsewhere.
- **N/A:** not applicable, with explicit rationale.

Severity: **CRITICAL** affects tenant isolation, contractual/financial integrity, custody, or goods-release authority; **HIGH** affects authorization, governance, auditability, or cross-platform correctness; **MEDIUM** affects maintainability, observability, or non-critical compatibility.

## 4. Cross-platform findings requiring careful interpretation

1. **Mobile is richer, not compliant by default.** It contains more supply-chain entities and route-level authorization controls, but the single-enterprise model conflicts with approved tenant architecture and the five composite-schema blockers remain.
2. **Web/Desktop tenant headers are not sufficient tenant isolation evidence.** Membership checks do not establish context replacement, stale-token invalidation, cache isolation, or Supplier hybrid access.
3. **A status field is not a governance workflow.** `disputed`, `active`, or `revoked` alone does not establish the required authority, transitions, audit, or hold semantics.
4. **OpenAPI is not runtime implementation.** Draft contract definitions are not evidence of route registration, authorization enforcement, or execution.
5. **Supabase Auth is not Supabase authoritative data.** OD-018 requires shared business-state authority, integrity, RLS and operational gates.

## 5. Overall disposition

- OD decisions: **22/22 approved as architecture/domain baseline**.
- Platform compliance: **not achieved**.

- Runtime database schema, actual deployed configuration, RLS policies, and production/staging behavior remain unverified.
- NAX/PAX authorization suites remain unexecuted unless separate exact-SHA run evidence is supplied.
- R0 implementation readiness remains **NOT ASSESSED**.
